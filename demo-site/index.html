User Guide · Transit Atlas Guide

System Concept & Human-in-the-Loop Workflow

Transit Atlas is a human-in-the-loop research workbench supporting urban transport planners. It does not replace human planners, but facilitates agile scenario investigation via a 7-step loop:

  • 01 Ask Question: State a planning question, target demographic or service window.
  • 02 Agent Proposes: Review literature, propose relevant datasets, indicators and calculation methods.
  • 03 Planner Approves Data: Audit provenance, limitations and calculation formulas. Halt if key data are missing.
  • 04 Python/GIS Processes: Download/process approved data into the standardized 1,597 study cells.
  • 05 Agent Proposes Weights: Suggest evidence-backed indicator weights with explicit justifications.
  • 06 Planner Adjusts Weights: Review, adjust or accept weights before committing to recalculation.
  • 07 Recalculate & Compare: Recalculate grid scores and map retained/added/exited candidate cells.

Spatial Atlas Navigation

The spatial canvas renders Singapore EPSG:3414 vector networks and 400 m grid cells:

• Layer Toggles: Toggle Planning Areas, Bus Routes, Bus Stops, and Study Grids in the layer tray.

• Cell Inspection: Click any grid cell to view its Planning Area, Grid ID, and status (Baseline / Retained / Added / Removed).

• Comparison Mode: In Results view, cells are colored by Retained, Added, and Removed, with an option to dim background transit networks.

Demo vs Full Local Workbench

• Public Demo: A static browser client demonstrating the interactive workflow across two vetted policy cases without requiring Python or API setups.

• Full Local Workbench: Includes the Python 3.12 GIS engine and Codex CLI backend to accept freeform questions, download live data and execute full 1,597-cell recalculations locally. Available on GitHub.
